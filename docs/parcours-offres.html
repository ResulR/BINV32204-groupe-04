Comment les offres arrivent à l'écran

Ce document décrit le parcours actuel de GET /offers, depuis le composant React jusqu'aux tables SQLite, puis le retour vers le tableau des offres.

Références principales : frontend/, backend/src/, backend/API.md et docs/architecture.md.

Parcours complet

Interface

OffersPage

frontend/src/pages/OffersPage.tsx appelle useOffers(token, onUnauthorized).

Hook

useOffers

frontend/src/hooks/useOffers.ts lance le chargement, annule une requête abandonnée et distingue une erreur 401 des autres erreurs.

HTTP frontend

getOffers

frontend/src/services/offers.service.ts appelle /api/offers avec le jeton dans Authorization.

Proxy Vite

Transmission

frontend/vite.config.ts transmet vers l'API sur le port 3000 et retire le préfixe /api. Le backend reçoit /offers.

Express

Route protégée

backend/src/app.ts place authenticate devant les routes. Puis offers.controller.ts vérifie authorize(canListOffers).

Règle métier

OffersService

backend/src/services/offers.service.ts choisit le filtre de visibilité : toutes les offres, publiées, ou celles du déposant connecté.

Accès aux données

OffersRepository

backend/src/repositories/offers.repository.ts exécute la requête SQL avec les filtres et joint les entreprises, années et périodes.

SQLite

Résultat

Les tables offers, companies, academic_years et periods fournissent les données.

Retour des données et affichage

SQL → modèle → DTO

Le repository renvoie un OfferDbo. Le mapper backend/src/mappers/offer.mapper.ts transforme les noms SQL (period_code, academic_year_label) en propriétés métier (period, academicYear), puis en DTO public. 

res.json(
  offersService.listOffers(user).map(toOfferDto)
);

Réponse HTTP → React

readJson valide la réponse avec isOfferList. Le hook stocke le tableau dans son état, puis OffersPage le transmet à OfferTable. 

<OfferTable offers={offers} />

Enfin, OfferTable.tsx affiche le titre, l'entreprise, l'année, PERIOD_LABELS[offer.period] et le statut.

Ajouter un filtre par période

Le filtre doit être appliqué dans la base et non uniquement masqué dans React : cela conserve la sécurité et évite de charger des offres inutiles. Le champ period existe déjà dans OfferDto et le repository joint déjà la table periods.

  1. 1. Interface — frontend/src/pages/OffersPage.tsx
    Ajouter une sélection P1, P2, OTHER et un état de période. Transmettre cette valeur à useOffers.
  2. 2. Requête frontend — frontend/src/hooks/useOffers.ts et frontend/src/services/offers.service.ts
    Ajouter le paramètre facultatif, par exemple GET /api/offers?period=P2. Réinitialiser ou relancer le chargement lorsque la période change.
  3. 3. Contrôleur — backend/src/controllers/offers.controller.ts
    Lire et valider req.query.period avec les codes autorisés (P1, P2, OTHER). Une valeur répétée ou inconnue doit produire 400 INVALID_QUERY.
  4. 4. Service — backend/src/services/offers.service.ts
    Conserver le filtre de visibilité déterminé par le profil et le compléter avec period, plutôt que de le remplacer. La période ne doit jamais permettre de contourner canListOffers.
  5. 5. SQL — backend/src/repositories/offers.repository.ts
    Ajouter period à OfferFilter et au paramètre de la requête, puis compléter le WHERE avec p.code = @period lorsqu'il est fourni.
  6. 6. Contrat et tests — backend/API.md, backend/http/offers.http, backend/tests/offers.test.ts et frontend/tests/OffersPage.test.tsx
    Documenter le paramètre, tester les trois périodes, la valeur invalide, les résultats combinés avec chaque profil et le rechargement de l'interface.

Point important

La période affichée aujourd'hui est déjà récupérée par la jointure SQL JOIN periods p, convertie par le mapper et rendue par OfferTable. L'ajout du filtre concerne donc le chemin de sélection des lignes, pas le format d'affichage.
